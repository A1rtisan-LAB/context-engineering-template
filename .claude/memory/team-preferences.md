# Team Preferences & Standards

## Code Style & Formatting
- Use 2-space indentation for JavaScript/TypeScript, HTML, CSS
- Use 4-space indentation for Python, Java, C#
- Apply automatic code formatting with Prettier/Black
- Maintain consistent naming conventions across codebase

## Technology Stack Preferences
- Prefer TypeScript over JavaScript for type safety
- Use React with functional components and hooks
- Apply Express.js for Node.js backend services
- Choose PostgreSQL for relational data, Redis for caching

## Documentation Standards
- Write comprehensive JSDoc/PyDoc comments for all public APIs
- Maintain up-to-date README files with setup instructions
- Document architectural decisions in ADRs (Architecture Decision Records)
- Keep API documentation synchronized with implementation

## Testing Philosophy
- Write tests first (TDD) for critical business logic
- Maintain separate unit, integration, and e2e test suites
- Use meaningful test names that describe behavior
- Mock external dependencies appropriately

## Communication Patterns
- Use clear, descriptive commit messages with conventional format
- Document breaking changes and migration steps
- Prefer asynchronous communication for non-urgent updates
- Schedule regular code review sessions and architecture discussions
