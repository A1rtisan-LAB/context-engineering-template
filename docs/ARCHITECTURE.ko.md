# 아키텍처 가이드

## 시스템 개요

Claude Code 템플릿 시스템은 유지보수성, 확장성, 사용 편의성을 위해 설계된 모듈형 아키텍처를 사용합니다.

## 핵심 컴포넌트

### 1. 코어 시스템 (`core/`)

#### 엔진 (`core/engine/`)
- **generator.sh** - 프로젝트 생성 엔진
- **validator.sh** - 검증 및 품질 보증  
- **synchronizer.sh** - 템플릿 동기화

#### 설정 (`core/config/`)
- **claude-template.config.json** - 통합 설정 시스템
- 프로젝트 유형, 권한, 검증 규칙을 위한 중앙화된 설정

#### 라이브러리 (`core/lib/`)
- **common.sh** - 공유 유틸리티 및 로깅
- **security.sh** - 보안 검증 및 안전한 작업
- **filesystem.sh** - 안전 검사를 포함한 파일 시스템 작업

### 2. 템플릿 시스템 (`templates/`)

```
templates/
├── .claude/                    # Claude Code 설정
│   ├── agents/                # 22개의 전문 AI 에이전트
│   ├── commands/              # 18개의 Claude Code 커맨드  
│   ├── memory/                # 컨텍스트 및 지식 템플릿
│   ├── workflows/             # 개발 워크플로우 템플릿
│   └── settings.json          # 기본 Claude Code 설정
├── CLAUDE.md                  # 프로젝트 지침 템플릿
├── INITIAL.md                 # 초기 설정 문서
└── README.template.md         # README 템플릿
```

### 3. 스크립트 (`scripts/`)

- **setup.sh** - 메인 프로젝트 생성 스크립트 (1,761줄의 모놀리스 대체)
- **validate.sh** - 검증 및 품질 검사
- **migrate-config.sh** - 설정 마이그레이션 유틸리티

### 4. 예제 (`examples/`)

프로젝트 유형별 예제 및 문서:
- **api-project/** - API 서버 템플릿 예제
- **frontend-project/** - 프론트엔드 애플리케이션 예제  
- **fullstack-project/** - 풀스택 애플리케이션 예제

## 아키텍처 원칙

### 1. 모듈성
- 각 컴포넌트는 단일 책임을 가짐
- 최대 파일 크기: 300줄
- 모듈 간 명확한 인터페이스

### 2. 보안 우선 설계
- 모든 사용자 입력의 검증 및 살균
- 경로 순회 공격 방지
- 안전한 임시 파일 처리
- 최소 권한 원칙

### 3. 설정 관리
- 통합 설정 시스템
- 환경별 오버라이드
- 스키마 검증
- 하위 호환성

### 4. 오류 처리
- 포괄적인 오류 보고
- 우아한 성능 저하
- 실패 시 자동 정리
- 상세한 로깅

## 데이터 플로우

```
사용자 입력 → 보안 검증 → 설정 로딩 → 
템플릿 처리 → 파일 생성 → 검증 → 출력
```

### 1. 입력 처리
1. 명령줄 인수 파싱
2. 입력 살균 및 검증
3. 보안 검사 수행

### 2. 설정
1. 통합 설정 로드 및 검증
2. 프로젝트 유형별 설정 적용
3. 권한 프로필 활성화

### 3. 생성
1. 스타터 템플릿 파일을 대상에 복사
2. `.claude/` 디렉토리 구조 생성
3. 패키지 내용 동적 발견 및 복사:
   - `@claude-code/` 하위 패키지 자동 발견
   - `src/` 디렉토리의 내용을 `src/` 레벨 없이 복사
   - 내부 패키지(예: 'core') 건너뛰기
   - 불필요한 파일 제외 (package.json, 테스트 등)
4. 플레이스홀더 교체 수행
5. 안전 검사와 함께 파일 작성

### 4. 검증
1. 생성된 프로젝트 구조 검증
2. 올바른 `.claude/` 구조 확인 (`src/` 하위 디렉토리 없음)
3. JSON 구문 검사
4. Claude Code 준수 확인
5. 최종 품질 보증

## 성능 특성

- **파일 작업**: 배치 처리로 최적화
- **메모리 사용량**: 최소 풋프린트 (~5MB)
- **실행 시간**: 일반적인 프로젝트에서 <2초
- **확장성**: 템플릿 수에 따른 선형 확장

## 생성된 프로젝트 아키텍처

### 디렉토리 구조
CLI로 생성된 프로젝트는 깨끗하고 Claude Code 준수 구조를 가집니다:

```
my-project/
├── .claude/                     # Claude Code 설정
│   ├── agents/                 # AI 에이전트 (파일이 바로 여기에)
│   │   ├── *.md               # src/ 하위 디렉토리 없음
│   ├── commands/               # 커맨드 (파일이 바로 여기에)
│   │   ├── *.md               # 커맨드 정의
│   │   ├── analyze/           # 카테고리별 구성
│   │   ├── implement/
│   │   ├── manage/
│   │   └── support/
│   └── workflows/              # 워크플로우 (파일이 바로 여기에)
│       └── *.md               # 워크플로우 정의
├── CLAUDE.md                   # AI 어시스턴트 지침
├── INITIAL.md                  # 기능 요청 템플릿
└── README.md                   # 프로젝트 문서
```

### 주요 설계 결정사항
- **심링크 없음**: 실제 파일 복사로 자체 포함된 프로젝트
- **src/ 하위 디렉토리 없음**: 파일이 카테고리에 직접 나타남
- **동적 발견**: 새 패키지 유형을 자동으로 처리
- **미래 대비**: 모노레포의 새 패키지가 자동으로 포함됨

## 향후 아키텍처

### 계획된 개선사항
1. **플러그인 시스템** - 확장 가능한 에이전트 및 커맨드 플러그인
2. **웹 인터페이스** - 선택적 웹 기반 프로젝트 생성기
3. **템플릿 레지스트리** - 커뮤니티 템플릿 공유
4. **고급 검증** - 스키마 기반 템플릿 검증

### 마이그레이션 경로
현재 시스템은 하위 호환성을 유지하면서 더 고급 아키텍처로의 점진적 마이그레이션을 지원하도록 설계되었습니다.
